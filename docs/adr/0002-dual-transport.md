# ADR-0002: WS 与 MQTT+UDP 双传输并存

- 状态: 已接受
- 日期: 2026-10-25
- 决策者: 维护者

## 背景

xiaozhi 协议存在两种服务端接入方式：

- WebSocket（`:8000/xiaozhi/v1/`）：音频与控制同连接，部署简单；
- MQTT 控制 + UDP/AES-128-CTR 音频：控制面与数据面分离，适合弱网与低延迟。

两者的控制语义一致（listen start/stop、tts abort、goodbye），音频封装不同。

## 决策

保留两条传输实现，控制面抽到 `src/control.rs`（`ControlLink` trait），
音频面各自实现；通过编译/配置二选一。状态机与协议解析放在
`xiaozhi-core`，两条传输共用。

## 后果

### 正面

- 共享状态机、控制消息与测试，避免两套业务逻辑漂移。
- 用户可按网关能力选择部署方式。

### 负面 / 代价

- 维护成本与代码体积增加；MQTT 路径的大缓冲必须放 PSRAM。
- 两条路径的行为差异需要真机验证（见 `docs/MQTT_UDP.md`）。

## 备选方案

只保留 WS：实现更简单，但无法接入只提供 MQTT 网关的部署。
