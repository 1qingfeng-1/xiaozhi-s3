# ADR-0004: OTA 暂只做 CRC，不启用签名

- 状态: 已接受（待修订）
- 日期: 2026-10-25
- 决策者: 维护者

## 背景

OTA 通过 `POST :8003` 获取清单，下载镜像后按 4KB 擦写，校验 CRC 后写
otadata 并复位。目前没有镜像签名，攻击者若能控制 OTA 服务端或 DNS，
即可下发任意固件。

## 决策

当前版本继续使用 CRC（防传输损坏），签名验签列入 ROADMAP，未启用。
`SECURITY.md` 明确说明该约束，要求仅在可信网络使用 OTA。

## 后果

### 正面

- 保持与现有服务端协议兼容，无需同步改造云端。
- CRC 实现简单，已由 `xiaozhi-core::ota` 覆盖单元测试。

### 负面 / 代价

- 不防篡改/伪造，供应链攻击面存在。
- 需要后续在 core 增加签名验证（Ed25519 + SHA-256），并升级清单格式。

## 备选方案

1. ESP-IDF Secure Boot v2：芯片级根信任，但需要改分区/efuse，开发板会锁死。
2. 应用层 Ed25519 验签：灵活、可回滚，推荐作为下一步（`sha256` 已在 core 实现）。
